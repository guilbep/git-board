Branch, review, merge: the PR is only the gate

guilbep, 30 Oct: stop saying PR or MR; it is a branch, reviewed before it is merged, and the branches of an issue live in its folder. To decide; nothing here is built.

[branches] name = "{kind}/{number}/{n}-{slug}". No branch is ever named test/2771, so git's folder rule always holds. {n} is counted from git: the issue's branches and the merges on dev that name them; never stored, never reused. The issue's number stays the first number in the name, as git-board's linking needs.

Words: three steps of a branch

  1. Branch
  2. Review
  3. Merge
  • Branch: made from the issue, in its folder.
  • Review: asked from the issue, answered in the issue (Approve, Request changes), as git-board's review already is.
  • Merge: from the issue, into dev.
  • The gate: GitHub's PR or GitLab's MR, as docs/prd/work-unit.md already calls it: opened by git-board when review is asked, because the forge runs its checks and rules there. Shown only as a link.

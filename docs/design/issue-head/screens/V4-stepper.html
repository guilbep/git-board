The next step: the arrow on the status box

One control (StatusStepper.vue, nextstep.ts): the box opens the workflow’s values, bold, with the value’s mark; the arrow moves to the next one, named in its tooltip. The last value closes the issue; a closed issue reopens.

No status

The arrow: Move to backlog, the workflow’s first value.

In the middle

Move to ready-for-validation, the next value by name.

Before the last

A check: Close as validated; the step onto the last value closes the issue, as the cycle’s sign-off does.

On the last, still open

A check: Close the issue.

Closed

A rotate-ccw: Reopen.

Blocked, held

A red blocked flag when a blocked-by is set; a yellow held when the GitHub Project disagrees on the status.

Hover

The arrow: --bg-subtle fill, --fg-muted border, the icon in red. The box the same fill and border on hover.

Focus

A 2px --fg-muted outline, 2px off.

Pressed

The words fade out (--t-fast), the PATCH goes, the new words fade in with their mark; nothing moves. On an error the old words come back with “Not saved”.

The box, opened

Status

A menu of the workflow’s values ([fields.status] options), each with its mark, the current one checked and bold; the focus lands on it, not on an input. Esc closes and gives the focus back to the box.

While it moves

Waits for the sync…

A move during a forge sync waits for its end, as every write does.

Not saved. The project file refuses this value.

Refused: the old words come back, the error beside them.

Task overview (why?)

Every kg-CO2-eq figure this product publishes comes from a backend formula (guardrail: the backend is the single source of truth). Today those formulas are covered unevenly: a few submodules have a dedicated formula test (test_research_facilities_common_formula.py, test_process_emissions_emissions.py), most only have schema tests. Nothing systematically checks that a given data entry produces the expected emission value across all submodules.

A drifted published number is the worst failure a data product can have. This task closes the gap in two phases: domain-authored reference examples first, then automated tests that pin them in CI.

Solution

Phase 1 — reference examples (domain · @person-c)

For each submodule below, add to the documentation 4–5 worked examples: the data entry (input values), the factor(s) and formula applied, and the expected kg-CO2-eq result. These examples become the spec the tests enforce.

  • Purchases: goods and services
  • Travel: flights, trains, cars
  • Research facilities (relies on the calculator's own results)

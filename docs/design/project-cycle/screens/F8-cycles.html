The cycle is the project's own

Today every issue walks the same seven steps, two of them skippable. Here the project declares its steps in [cycle], a kind of issue may have its own list, and the page follows: the rail has as many cells as there are steps, the flow as many segments, the numbers are the rail's. The gates don't move: they belong to the kind of step.

The description is always the first entryAn issue has a text whether or not Intent is a step. Without an Intent step there is no verdict and no criteria gate; the text still folds under the current step's workspace.
A comment carries its step's id, not its numbercycle:step = qa, review, intent. The number is the rail's and changes with the list; the id doesn't. Today's "1" to "7" map onto the default list.
Gates belong to the kind of stepReview always wants an approval, a sign-off its role's person, Intent its criteria. The project picks which kinds, in which order, and which kinds of issue get which list; risk still skips a step inside the list.

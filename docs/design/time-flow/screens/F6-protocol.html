A sketch, not settled · key names are a proposal, in the core's form

One comment, three readings

Nothing new is stored. A version is the core's edit-text on the body; an anchor, a reply, a verdict and a step are meta keys on the comment, the way cycle:step and review:path already are. GitHub #37 gets every comment flat and in time order; the keys ride in the marker sync already hides on the last line, and come back on pull.

A flat comment, readable as is: the quote says where, the block shows what. The marker is the one sync already writes, with the keys appended; pulled back, it is stripped and the keys become meta again. Unlike review:* line comments, which stay local, a thread on the body is posted. On GitLab the thread becomes a discussion instead of a quote.

Where each thing lives
  1. The thingIn the coreOn GitHub #37 · GitLab
  2. The description, v2edit-text with target <issue>:0. Versions are counted, never stored: the n-th edit that changes text is vn.The issue body, edited; the forge keeps the edit history. Plus a comment: "Published v2 · § intro, § Expected, § Workaround changed".
  3. A tick, at step 07An edit-text on the body that flips - [ ] to - [x] and nothing else: a tick, not a version.The body, edited.
  4. A section anchorthread:anchor = body@v1/expected#3: the text, its version, the section's slug, the item. A reply inherits its root's anchor. Later: plan@<commit>/steps#4 for a plan file.A quote header on the comment: > **On v1 · § Expected · 3** · _the line_.
  5. A replythread:reply-to = <comment id>, the thread's root.A flat comment, the quote header repeated. GitLab: a reply in the same discussion.
  6. A suggested editThe body carries a ```suggestion block · thread:kind = suggestion. Apply writes the next version, then set-meta on the root: thread:resolved = v2, thread:applied = <edit op id>.The same block, shown as code; still readable.
  7. A verdictA comment with spec:verdict = approve | request-changes and spec:on = body@v2; approving moves the status, as a step's button does today.A comment whose first line is bold, then the status label, as today.
  8. The stepcycle:step = 01, as today: set by the composer from the issue's step at that moment, never typed.In the marker only; the forge shows nothing, needs nothing.
  9. A milestoneA change-labels or set-status op, as today; PR events arrive through sync.The label, the state, the PR link.
  10. Carried, outdated, resolvedCarried and outdated are computed: an anchor is matched against the later version's section text, unchanged means carried, changed means outdated. Resolved is thread:resolved on the root, set by Apply or by a person.Not written. git-board's reading only; GitLab resolves its discussion.
  11. The round tripThe thread:, spec: and cycle:step keys are appended to the marker sync writes; pull strips the marker and restores them as meta, so a comment that went out and came back is the same comment.Invisible on GitHub and GitLab. A comment typed on the forge has no keys: a plain comment on the issue, in the step current at pull.

Choose the release remote; never assume origin

docs/plans/31-release-remote.mdstatus: draft · v2 by Claude Code, 10 min agoWorktree 31-release-in-a-fork-s-cloneAgent Claude Code, in plan modeDraft PR #41, the plan onlyOpen the session

A cut reads tags from, pushes to and publishes on origin whenever a remote of that name exists. In a fork's clone that is upstream, which the token can't write.

Options

OptionA fork's cloneVerdict
A · [release] remote, else the one remote the token can push toWorks with no setup; Settings suggests the keyChosen
B · Ask on every cutWorks, asks each timeRejected: noise
C · Keep origin, warnStill pushes upstreamRejected: unsafe

Steps

  1. release.Remote() reads [release] remote, else the only remote the token can push to; none or several: the cut stops and says which.
  2. ConfigRepo stops naming origin.
  3. Settings › Releases suggests the key on a fork, and why.
  4. The trunk is the chosen remote's default branch, read from its HEAD: bridge-sync on the fork.

Tests first

TestCutPicksThePushableRemote: a clone with origin read-only and fork writable. It fails before the fix.
